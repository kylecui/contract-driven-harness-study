# 论文修改意见 v2（基于真实模型复现实验）

**依据**：除文本审读外，新增一手实测证据——用 Qwen3-8B（SiliconFlow 真实 API）独立复刻 Stage B v5.4 协议，经 4 轮 repair-loop 从 0/40 收敛到 40/40（Wilson [0.912, 1.000]），并在 petfishframework 与 LangChain 双框架验证。以下意见按"实测后优先级"重排。

---

## 第一优先级：论文最强的部分被自己的叙事埋没了（实测后最重要的修改）

**实测发现**：论文的核心机制是真实可复现的——我们独立走出了 0/40→40/40 的修复曲线，且 v1 的失败模式（next_action 缺枚举值声明）与论文 Stage B v5 的记录逐字同构。但论文把这个最有说服力的故事拆散在 Stage 6/7e/7p/B 的内部代号里。

1. **把 repair-loop 收敛曲线提升为论文的主图（Figure 1）**：X 轴迭代版本，Y 轴严格通过率，每个拐点标注修复的义务。我们实测的曲线（0% → 52.5% → 82.5% → 100%）就是这张图该长的样子——它比任何文字都更能传达"可靠性是逐义务攒出来的"。
2. **给每个失败模式一张"义务卡片"**：失败现象 → 隔离出的义务 → 契约 diff → 对应 known-bad fixture → 修复后通过率。我们实测产生的 10 个 KB 卡片证明这种格式完全可行，且是论文最独特的可迁移资产。

## 第二优先级：实测暴露的、论文没回答的方法论缺口

3. **必须给出"模型失败 vs 评估器缺陷"的判定流程**。我们实测中直接踩中：v1 的 attestation 检查要求含"未改变"字样，模型语义正确但措辞不同 → 这是评估器缺陷而非模型失败。论文承认评估器会过拟合，但没有区分两类失败的操作程序。建议增加一条规则：**修复前先问"义务是否已在模型可见的契约中显式声明"——未声明的是契约缺陷，已声明仍失败的才是模型失败**。我们的 v1→v2 修复全部属于前者，这个区分决定了修复动作该落在哪。
4. **补充"义务覆盖清单"概念**。实测发现：v4 声明了"所有状态标识必须使用规范名"，但模型仍在 attestation 字段里用改写名——义务声明了却没覆盖到每个输出字段。建议契约模板增加一个 checklist：每个全局义务 × 每个输出字段的覆盖矩阵。这是我们实测中最后一个 40/40 障碍的根源。
5. **温度/provider 参数必须写进冻结协议**。我们对比时发现 petfishframework 侧未显式固定 temperature（LangChain 侧 t=0），导致两框架结果不可严格配对。论文称"provider-backed runs use temperature 0"，但应把温度、provider、模型版本快照、提示词哈希全部列为协议冻结项并给出校验方法——否则"frozen protocol"的 claim 存在缺口。

## 第三优先级：用跨框架证据加固可迁移性 claim

6. **新增跨框架复现实验（哪怕小规模）**。我们已验证：同一契约栈在 petfishframework（40/40）和 LangChain（37/40，差异在统计噪声内）上都把同一 8B 模型拉到高契约遵循度。论文反复强调 "PEtFiSh is the implementation context, not the transferable claim"——**用 2-3 个机制原子在 LangGraph 或 LangChain 上复现，这句话就从声明变成证据**。这是回应审稿人"结论绑定私有实现"质疑的最便宜方式。
7. **补一个"契约演进账本"附录**。实测中我们发现最有审计价值的中间产物是每轮契约的 diff（v1→v5 逐版变化 + 触发它的失败运行 ID）。论文的证据账本（evidence ledger）概念应显式包含契约版本演进，而不仅是运行结果。

## 第四优先级：仍然成立的文本与结构问题（与实测无关但必修）

8. **修复引文系统**：`\cite{P2_EXT_...}` key 裸露、无参考文献列表，投稿级硬伤。
9. **内部实验代号翻译**：Stage 6/7r/7e/7p/B 体系对外部读者不透明，加实验总览表（代号→问题→设计→n→结果），细节下沉附录。
10. **正式介绍或去除 PEtFiSh**：当前外部读者无法复现；好消息是该框架已公开（PyPI: petfishframework, v1.0 核心 API 冻结），可直接引用并给出版本号。
11. **Related Work 升级为逐篇对比**：尤其 Agent Behavioral Contracts (arXiv:2602.22302) 与 AgentSpec (arXiv:2503.18666)，与本文正面重叠，不引必被质疑。
12. **多模型覆盖**：我们的实测同样只有 Qwen3-8B 一个模型——这既是论文的缺口也是我们的。至少补一个不同家族 8B 模型跑冻结协议。
13. **量化契约成本**：我们实测一轮 repair-loop 的增量成本≈一次失败分析 + 一处契约 diff + 一个 KB fixture + 40 次 API 调用（Qwen3-8B 下 API 成本可忽略，主要成本是人的失败分析时间）。论文应给出类似口径的成本核算框架，回答"写契约 vs 用更强模型"的盈亏平衡点。

## 第五优先级：表述校准

14. **40/40 的表述建议改一个字**：论文说 "maintained strict contract adherence"——实测表明更准确的表述是"修复后的契约使模型达到并可复现 strict adherence"，因为稳定性是**修复循环的产物**而非协议初版的属性。建议在 Results 开头就展示"初版契约的失败率"，让 40/40 的含金量（它是收敛终点而非起点）不被误读。
15. **标题/定位**：建议副标题体现 case-study 性质（如 "...: A Mechanism-First Case Study"），与正文诚实基调一致。

## 总结：实测后评价的变化

| 维度 | 纯文本审读时 | 实测后 |
|---|---|---|
| 核心机制可信度 | "窄而干净，但单模型单任务" | **上调**：独立复现成功，失败模式逐字同构，不是孤例 |
| repair-loop 可操作性 | "看起来合理" | **上调**：4 轮收敛的真实路径已验证，成本可接受 |
| 主要缺口 | 规模小、成本未量化 | 新增两个实测发现的缺口：模型失败/评估器缺陷的判定程序、义务的字段级覆盖问题 |
| 可迁移性 claim | 无证据 | 我们提供了初步证据（双框架），论文应自己补上 |

**一句话**：实测后我对论文机制的信心显著上升——修改重点应从"补证据"转向"把已被验证的修复叙事提到前台 + 补上失败分类与义务覆盖两个方法论缺口 + 用低成本跨框架实验把可迁移性从声明变成证据"。
